# Stability Analysis of Pitchfork and Swift–Hohenberg Models

MATLAB code for simulating stochastic pitchfork and Swift–Hohenberg systems, estimating model coefficients from spatiotemporal data, and evaluating whether fitted coefficients can distinguish different dynamical regimes.

The repository is organised into separate simulation, analysis, and combined-workflow folders for each model:

```text
.
├── Pitchfork/
│   ├── Simulation/
│   ├── Analysis/
│   └── Combine/
│
└── Swift_Hohenberg/
    ├── Simulation/
    ├── Analysis/
    └── Combine/
```

## Overview

The code supports two related workflows:

1. **Pitchfork model**
   - Simulate stochastic pitchfork trajectories for a sweep of negative values of `mu` and both signs of the cubic coefficient `s`.
   - Estimate the model coefficients at several observation horizons.
   - Use the estimated cubic coefficient, `s_hat`, as a classification score.
   - Evaluate classification performance with ROC curves and AUC values.

2. **Swift–Hohenberg model**
   - Simulate stochastic spatial patterns on a periodic domain using a Fourier/FFT solver.
   - Estimate linear and cubic coefficients from the simulated spatiotemporal data.
   - Estimate the most unstable wavenumber and its corresponding growth rate.
   - Evaluate classification performance using the estimated cubic coefficient.
   - Compare estimated and theoretical dispersion relations.

The combined scripts perform repeated simulations, analyse valid realisations, save processed results, and generate figures for further analysis.

## Requirements

The code is written for MATLAB and requires the following functionality:

- MATLAB with support for scripts, functions, structures, cell arrays, and `parfor`.
- Parallel Computing Toolbox for parallel simulation batches.
- Statistics and Machine Learning Toolbox for:
  - `perfcurve`
  - `ksdensity`
  - `prctile`
- MATLAB graphics functionality for:
  - `exportgraphics`
  - `savefig`
  - tiled layouts and figure annotations
- A MATLAB version that supports string scalars such as `"White"` and the plotting functions used in the scripts.

The repository does not include external data files. The combined scripts generate the stochastic data when no compatible saved result is found.

## Pitchfork workflow

### Main functions

#### `simulate_pitchfork`

Generates one stochastic pitchfork trajectory.

```matlab
[t_vec, u_vec] = simulate_pitchfork( ...
    mu, s_true, tmax, tsteps, noiseType, sigma, InitialScale)
```

Inputs used by the combined workflow:

| Input | Description |
| --- | --- |
| `mu` | Linear pitchfork coefficient. The example sweep uses negative values generated by `-logspace(-1,2,50)`. |
| `s_true` | True cubic-coefficient sign used to define the classification class. The workflow uses `s_values = [1, -1]`. |
| `tmax` | Maximum simulation time. |
| `tsteps` | Number of time samples, calculated from `tmax` and `dt_target`. |
| `noiseType` | Noise specification. The example uses `"White"`. |
| `sigma` | Noise amplitude. |
| `InitialScale` | Initial-condition scaling parameter. The example uses `0`. |

Outputs:

- `t_vec`: simulation time vector.
- `u_vec`: simulated pitchfork state data. The combined script accepts either time-by-row or time-by-column output and converts it internally to time-by-row format.

#### `analyze_pitchfork`

Estimates pitchfork coefficients from a trajectory prefix.

```matlab
[theta_sub, output2, output3] = analyze_pitchfork(u_sub, t_sub);
```

The combined workflow uses `theta_sub` and stores its first two components. The second component is selected as the ROC score:

```matlab
kc_shat = 2;
```

The remaining outputs are currently ignored by the combined script and are represented by `~` in the function call.

### Pitchfork combined script

The pitchfork combined workflow is represented by `test_code_pitchfork_loops.m`. It:

1. Defines the `mu`, `s`, noise, time-step, and realisation settings.
2. Creates simulation batches using deterministic seed IDs.
3. Runs independent seeds in parallel with `parfor`.
4. Rejects failed, non-finite, or explosively large trajectories.
5. Estimates `theta` at every requested observation horizon.
6. Adaptively reduces the active maximum horizon if too few simulations remain valid at the longest horizon.
7. Computes AUC values using the selected `s_hat` component.
8. Produces AUC, density, ROC, and optimal-threshold figures.
9. Saves processed results in a settings-specific `saved_data` folder.

Example settings from the current workflow:

```matlab
noiseType = "White";
InitialScale = 0;
sigma = 1;
mu_values = -logspace(-1,2,50);
n_realizations = 20;
tmax_values = [1, 2, 5];
dt_target = 0.01;
s_values = [1, -1];
kc_shat = 2;
```

## Swift–Hohenberg workflow

### Main functions

#### `simulate_scaled_SH_Fourier`

Generates stochastic Swift–Hohenberg data on a periodic spatial domain using an FFT-based solver.

```matlab
[tvec_full, xvec_full, u_full] = simulate_scaled_SH_Fourier( ...
    mu, s_true, gamma_value, tmax, tsteps, L, xsteps, ...
    noiseType, correlation_length, NoiseScale, InitialScale)
```

Inputs used by the combined workflow:

| Input | Description |
| --- | --- |
| `mu` | Linear Swift–Hohenberg coefficient. The example sweep uses negative values generated by `-logspace(-1,2,20)`. |
| `s_true` | Cubic-coefficient/sign class. The workflow uses `s_values = [1, -1]`. |
| `gamma_value` | Fixed Swift–Hohenberg parameter. The example uses `1`. |
| `tmax` | Maximum simulation time. |
| `tsteps` | Number of time samples calculated from `tmax` and `dt_target`. |
| `L` | Periodic spatial-domain length. The example uses `20*pi`. |
| `xsteps` | Number of unique periodic spatial grid points. It is calculated from `L/dx_target`; the example gives `100`. |
| `noiseType` | Noise specification. The example uses `"White"`. |
| `correlation_length` | Spatial noise-correlation length. The example uses `0`. |
| `NoiseScale` | Noise-strength scaling factor. The example uses `1`. |
| `InitialScale` | Initial-condition scaling parameter. The example uses `0`. |

Outputs:

- `tvec_full`: simulation time vector.
- `xvec_full`: spatial grid on the periodic domain.
- `u_full`: spatiotemporal Swift–Hohenberg field.

The periodic grid uses unique points on `[0,L)`, so the endpoint `x = L` is not duplicated. The script checks that the requested spacing is consistent with the domain length.

#### `analyze_SH_scaled`

Estimates Swift–Hohenberg coefficients and dispersion-related quantities from a spatiotemporal field.

```matlab
[theta_sub, kmax_sub, lambda_sub] = ...
    analyze_SH_scaled(u_sub, t_sub, xvec_full);
```

Outputs used by the combined workflow:

| Output | Description |
| --- | --- |
| `theta_sub` | Estimated model coefficients. The first four components are stored. |
| `kmax_sub` | Estimated wavenumber associated with the most unstable mode. |
| `lambda_sub` | Estimated growth rate/eigenvalue at that wavenumber. |

The fourth theta component is used as the classification score:

```matlab
kc_shat = 4;
nThetaComp = 4;
```

### Swift–Hohenberg combined script

The Swift–Hohenberg combined workflow is represented by `test_code_chatgpt.m`. It:

1. Defines the parameter sweep, periodic spatial grid, time step, noise settings, and observation horizons.
2. Simulates independent stochastic realisations with the periodic FFT solver.
3. Analyses each trajectory prefix at the requested observation horizons.
4. Rejects invalid, non-finite, or explosively large fields.
5. Stores estimated theta coefficients, dominant wavenumbers, growth rates, and seed IDs.
6. Adaptively reduces the active observation horizon when too few realisations reach the longest horizon.
7. Computes AUC values using the selected cubic-coefficient estimate.
8. Generates AUC, density, ROC, and dispersion-summary figures.
9. Saves processed results in a settings-specific `saved_data` folder.

Example settings from the current workflow:

```matlab
noiseType = "White";
correlation_length = 0;
InitialScale = 0;
NoiseScale = 1;
mu_values = -logspace(-1,2,20);
n_realizations = 100;
L_values = 20*pi;
dx_target = 0.2*pi;
dt_target = 2.5e-4;
tmax_values = [0.1, 0.2, 0.5, 1, 2, 5, 10, 20];
gamma_value = 1;
s_values = [1, -1];
kc_shat = 4;
nThetaComp = 4;
```

## Running the workflows

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/<your-repository>.git
cd <your-repository>
```

Replace the repository URL with the URL of the new repository.

### 2. Add the folders to the MATLAB path

From MATLAB, either set the repository root as the current folder or add the model folders recursively:

```matlab
repoRoot = pwd;
addpath(genpath(repoRoot));
savepath;   % Optional: save the path for future MATLAB sessions
```

Alternatively, add only the folders required for a particular workflow:

```matlab
addpath(genpath(fullfile(pwd, 'Pitchfork')));
addpath(genpath(fullfile(pwd, 'Swift_Hohenberg')));
```

### 3. Run the combined script

For the pitchfork workflow:

```matlab
run('Pitchfork/Combine/test_code_pitchfork_loops.m');
```

For the Swift–Hohenberg workflow:

```matlab
run('Swift_Hohenberg/Combine/test_code_chatgpt.m');
```

The exact paths should be adjusted if the scripts are given different filenames in the repository.

### 4. Check the user settings

Before running a full experiment, consider testing with:

- fewer values in `mu_values`;
- fewer `n_realizations`;
- a shorter `tmax_values` list;
- a larger `dt_target` only when numerically appropriate;
- a smaller spatial grid for initial debugging.

For production simulations, use the settings required by the experiment and verify numerical stability, memory use, and available parallel workers.

## Saved results and figures

Both combined workflows create a settings-specific output folder in the current working directory. The exact folder name records key simulation settings.

Typical output categories include:

```text
saved_data/
├── *.mat

a uc_plots/
ridge_plots_all/
roc_plots_per_time/
threshold_plots/
dispersion_summary_panels/
```

The exact subfolders depend on which combined script is run.

### Processed MAT-files

The processed result files can contain:

- `per_theta`: fitted coefficient estimates grouped by model component, `mu`, `s`, domain length, and observation horizon;
- `per_theta_seeds`: seed IDs corresponding to the fitted estimates;
- `auc_all_all`: AUC values for the classification score;
- `per_kmax`: estimated dominant wavenumbers for the Swift–Hohenberg model;
- `per_lambda_max`: estimated growth rates at the dominant wavenumbers;
- parameter and numerical settings used for the run.

If a compatible MAT-file already exists, the corresponding combined script loads the processed data and skips the expensive simulation stage. The plotting and downstream analysis can then be repeated without rerunning the simulations.

## Numerical and methodological notes

- The simulations use seeded random-number streams so that individual realisations can be identified and, subject to the solver and MATLAB environment, reproduced.
- Simulations are performed in batches and independent seeds are distributed with `parfor`.
- A trajectory is rejected when the simulator or analysis function fails, when the output is empty or has an incompatible orientation, or when the data contain non-finite or excessively large values.
- Observation horizons are implemented by analysing prefixes of a trajectory generated up to the active maximum horizon.
- The AUC calculation treats `s > 0` as the positive class and `s < 0` as the negative class.
- For the Swift–Hohenberg model, the spatial grid is periodic and uses unique points on `[0,L)`.
- The dispersion summaries compare estimated curves and dominant-mode quantities with the theoretical Swift–Hohenberg relation used in the script.

## Reproducibility

For a reproducible run, record:

- MATLAB version;
- operating system;
- available parallel workers;
- repository commit or release;
- all user settings in the combined script;
- random-number generation method and seed convention;
- versions of the simulation and analysis functions.

Because the simulations are stochastic and may use parallel execution, exact numerical results can depend on MATLAB version, hardware, and parallel-pool configuration even when the same seed IDs are used.

## Troubleshooting

### MATLAB cannot find a function

Check that the relevant folder is on the MATLAB path:

```matlab
which simulate_pitchfork -all
which analyze_pitchfork -all
which simulate_scaled_SH_Fourier -all
which analyze_SH_scaled -all
```

Each required function should resolve to the intended file in this repository.

### `parfor` is unavailable

Install or activate the Parallel Computing Toolbox, or temporarily replace `parfor` with `for` for debugging. This may substantially increase runtime.

### The script rejects all realisations

Check:

- the time-step stability of the simulator;
- the values of `NoiseScale` or `sigma`;
- `u_explosion_threshold`;
- the observation horizons;
- the orientation and dimensions of the simulator outputs;
- whether the analysis function accepts the supplied data format.

### A saved file is loaded unexpectedly

The scripts use settings-specific paths and load existing compatible MAT-files. Delete or rename the relevant `saved_data` folder, or change the settings used to construct `base_dir_root`, if a fresh simulation is required.
